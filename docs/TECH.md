## Контракт EyeState
```ts
export type Zone = 'L' | 'C' | 'R';          // MVP; позже 3×2

export type EyeEvent =
  | 'blinkStart' | 'blinkEnd'
  | 'closeStart' | 'closeEnd'
  | 'zoneChange'
  | 'signalLost' | 'signalBack';

export interface EyeState {
  t: number;                        // ms, монотонное: performance.now() или время реплея от 0
  confidence: number;               // 0..1
  lost: boolean;                    // сигнал потерян (после дебаунса); пока true, остальные поля заморожены
  gaze: { x: number; y: number };   // -1..1 после калибровки; x>0 — правая часть экрана, y>0 — верх
  zone: Zone;
  blink: boolean;                   // веки сомкнуты, но не дольше closedMs
  closed: boolean;                  // сомкнуты дольше closedMs; никогда не true вместе с blink
  wink: 'L' | 'R' | null;           // анатомический глаз игрока
  wide: number;                     // 0..1
  squint: number;                   // 0..1, прищур при открытых глазах (кандидат на лидар, GDD)
  events: EyeEvent[];               // накопленные с прошлого poll()
}

export interface EyeSource {
  readonly kind: 'tracker' | 'fallback' | 'replay';
  start(): Promise<void>;
  stop(): void;
  poll(now: number): EyeState;      // последнее состояние + все события с прошлого poll
}
```

**Семантика век.** В момент смыкания нельзя знать, моргание это или закрытие, поэтому любое смыкание начинается как `blink`:
- короткое моргание: `blinkStart → blinkEnd`;
- закрытие: `blinkStart → closeStart → closeEnd` (без `blinkEnd`; `blink` сбрасывается, `closed` поднимается);
- «веки сомкнуты» для игры = `blink || closed`. Фонарик гаснет на `blinkStart`, а не на `closeStart`.
- перед `signalLost` открытые интервалы закрываются (`blinkEnd`/`closeEnd`), поэтому каждое `*Start` имеет парный `*End`.

**События не теряются.** Трекер работает на частоте камеры (~30 Гц), игра — на частоте рендера. Источник копит события между вызовами `poll()` и отдаёт все разом. Моргание короче кадра рендера придёт как `blinkStart` и `blinkEnd` в одном poll.

**Старт.** Трекер стартует в `lost: true` и шлёт `signalBack`, когда лицо стабильно найдено. Игра стартует на паузе.

Сухость — игровое правило, поэтому она живёт в `game/dryness.ts`, а не в input.

Есть три источника EyeState: Tracker, Fallback и Replay. Игра не знает, какой из них сейчас работает. Это позволяет тестировать без камеры, а агенту — проверять логику.

### Два слоя данных
- **`RawFrame`** — числовой выход трекера за кадр: нужные blendshapes глаз, прокси поворота головы, положение зрачка, яркость лица. Это формат фикстур. Replay гонит RawFrame через тот же `gaze.ts`, поэтому фикстуры тестируют и детекцию, а не только игру.
- **`FaceFrame`** — 478 landmarks. Только для визуализации (лидар-окно, оверлей), в фикстуры не пишется: это геометрия лица, то есть биометрия.

## Трекинг

### Сигналы
- **Blink:** `eyeBlinkLeft` / `eyeBlinkRight`, нормированные калибровкой (0 = открыты, 1 = закрыты). Комбинация — `config.lid.combine`. По умолчанию `min` (сомкнуты оба глаза): ложное моргание хуже пропущенного. Ложное — игрок с открытыми глазами видит темноту и перестановку. Пропущенное — просто упущенный шаг. Режим «один глаз» — `L`/`R`. Окончательно решить в M0 по фикстурам.
- **Gaze:** `eyeLookIn/Out/Up/Down` × `Left/Right` плюс поворот головы. Голова даёт грубое направление, глаза уточняют. Без учёта головы зона будет залипать: люди смотрят и глазами, и головой.
- **Поворот головы** — прокси из landmarks (нос относительно краёв овала лица), а не из transformation matrix: раскладка матрицы в типах MediaPipe не задокументирована. Абсолютные углы не нужны, масштаб и знак снимает калибровка.
- **Iris landmarks (468–477):** для лидар-окна и как альтернативный gaze-сигнал (`config.gaze.eyeSignal = 'iris'`, положение зрачка в прорези глаза). Какой сигнал лучше, решить в M0.
- **Confidence:** в результате FaceLandmarker его нет. Считаем сами: наличие лица × `smoothstep` по средней яркости bbox лица (уменьшенный кадр раз в N кадров, пиксели не покидают память).

Соответствие Left/Right и зеркалирование видео проверить в debug-оверлее, не предполагать. Знак gaze от этого не зависит: калибровка меряет сырое значение при взгляде влево и вправо и строит отображение с правильным знаком. Для wink есть `config.lid.swapLR`.

### Калибровка (v2)
Мастер (`ui/calibration.ts`), **на каждом входе с камерой**, ~30 с. Esc при сохранённом профиле — играть с прошлым, без профиля — назад на титул.
0. **Предпроверка**: лицо, свет (`luma ≥ signal.lumaOk`), расстояние (размах внешних уголков глаз, `calibration.precheck` — оценка, не замер), лицо по центру; всё в норме 1 с — дальше. В центре — лидар-портрет глаз (`render/lidarEyes.ts`).
1. **9 точек** сеткой 3×3 на ±0.75 экрана, центр первым. Точка засчитывается, только когда взгляд устоялся: окно кадров без моргания с малым разбросом сырых осей (`isStable`). Не устоялся за 3.5 с — повтор, потом точка пропускается; нужно ≥ 6 годных.
2. **5 морганий** по звуку, **закрытые глаза** 2.5 с.
3. **Валидация**: 4 новые точки, средняя ошибка → `profile.accuracy`, отчёт в % экрана.
4. **Живая проверка**: точка идёт за взглядом 3 с.
5. **Результат**: точность в % экрана, предупреждения; продолжить (Enter, клик, закрыть и открыть глаза) или повторить (R).

**Лидар-портрет глаз.** Окно вокруг глаз по landmarks (уголки + брови, выровнено по наклону головы, сглажено), кадр камеры растеризуется в сетку 200×80 в памяти и сразу забывается — пиксели никуда не уходят (CLAUDE.md, правило 3). Точки-полутона: светлее — крупнее; рельеф по яркости, лёгкий поворот за головой, края растворяются. Поверх — контуры век, кольца радужек, раскрытие OD/OS. Метрики предпроверки считаются там же: FaceFrame дальше не уходит.

Из этого `CalibrationProfile`:
- **взгляд** — ridge-регрессия по признакам `[1, yaw, pitch, lookH, lookV, irisX, irisY]` на всех стабильных кадрах, каждая точка весит одинаково. Вклад головы и глаз — персональный, а не константа v1; регрессия гасит шумные признаки и перекрёстную связь осей. Отказ, если взгляд влево/вправо почти не меняет сигнал (R² < 0.5);
- **веки** — открытые/закрытые по каждому глазу; пороги on/off из шума конкретного человека (робастная σ по необрезанному сигналу, оба глаза), пики морганий ограничивают on сверху; шумно — подтверждение 2 кадрами (+1 кадр латентности);
- **closedMs** — из длительности морганий.

Во время игры:
- **адаптивный baseline** открытых глаз догоняет свет и усталость (τ 20 с, только пока веки уверенно открыты, не дальше половины разделения);
- **перецентровка** за ~2 с (одна точка в центре сдвигает только ноль) — `R` в игре или кнопка в оверлее;
- профили v1 (без регрессии) продолжают работать через кусочно-линейные оси.

Проверено на синтетике (`tests/calibration.test.ts`): разные люди (головой / глазами / зеркало) — ошибка валидации < 0.12; при перекрёстной связи и шумных глазах регрессия точнее v1 минимум на 30%; шумные веки — ни одного ложного моргания за 2 минуты; дрейф baseline на +0.3 — все моргания пойманы.

### Фильтрация
- **One Euro filter** на gaze: мало джиттера в покое и мало лага при резком движении.
- **Гистерезис зон:** порог входа в зону выше порога выхода, плюс dwell time перед сменой.
- **Blink:** гистерезис (порог включения выше порога выключения) и минимальная длительность против шума. Моргание отличается от закрытых глаз по длительности, порог берётся из калибровки.
- **Во время моргания gaze замораживается:** при закрытых глазах `eyeLook*` выдают мусор. Заморозка держится ещё `holdAfterShutMs` после открытия.
- **Кадры с низким confidence** не обновляют состояние даже до срабатывания `signalLost`.

### Потеря сигнала
`confidence` ниже порога дольше `lostAfterMs` → `signalLost` → игра на паузе с диегетической статикой. Возврат — выше второго порога дольше `backAfterMs` (гистерезис и дебаунс, чтобы один выпавший кадр не ставил паузу). Не трактовать как закрытые глаза: иначе игрок умирает из-за плохого света.

В меню дать яркую рамку-«лампу»: экран подсвечивает лицо.

### Латентность
Цепочка: экспозиция и доставка кадра (до ~33 мс при 30 fps) + инференс (замерить в M0) + подтверждение в детекторе (`confirmFrames`). Грубая оценка — 50–100 мс, моргание длится 100–400 мс. Следствия:
1. Всё, что директор меняет на моргании, коммитится в первом игровом тике после `blinkStart`.
2. После открытия глаз игрок ещё ~латентность видит темноту. Это «фонарик гаснет на время моргания плюс задержка» из GDD, не баг.
3. Вне луча — полная темнота без ambient, иначе смена поз видна в этом хвосте.
4. Каждый `confirmFrames` сверх 1 добавляет кадр латентности. Цена защиты от шума — время.

### Фикстуры и протоколы
Фикстура = поток `RawFrame` + метки-сигналы (cues) + профиль калибровки + условия (очки, свет). Записывается по протоколу из `protocols.ts`: игроку дают звуковой и визуальный сигнал («моргни», «смотри влево», «закрой глаза», «закрой камеру рукой»), и время сигнала пишется в фикстуру. Так у фикстуры есть разметка, и `evaluate.ts` считает метрики без ручной проверки: сколько сигналов поймано, сколько лишних срабатываний, правильная ли зона. Критерии — в `config.acceptance`.

Кадры хранятся колонками с округлением до 3 знаков: минута записи весит ~200 КБ.

Синтетика (`tests/synthetic.ts`) генерирует такие же потоки с известной разметкой и шумом. Это страховка для логики, но не замена живым фикстурам: реальный шум MediaPipe синтетика не знает.

### Производительность
- Трекинг не обязан идти каждый кадр рендера. Отдельный цикл через `requestVideoFrameCallback`, частоту снижать при падении fps.
- Начинать в main thread. Выносить в Worker только если замеры покажут, что рендер страдает.
- Цель: стабильные 60 fps рендера на среднем ноутбуке. Проверять замерами.

## Рендер: только лидар
Обычной графики нет (GDD v2 → Столпы). Мир — невидимые меши (`render/scanScene.ts`), игрок видит только облака точек.

**Импульс.** `CubeCamera` снимает сцену-мишень в кубическую карту `RGBA16F` 512² из точки игрока. Шейдер мишени пишет в пиксель: дистанцию, `материал + 16·(вид+1)`, интенсивность (отражение 905 нм × угол падения), радиальную скорость (доплер). Окклюзия и лидарные тени — бесплатно из z-буфера. Силуэт — обычная геометрия (6 поз, видна одна) со своей скоростью: скан ловит его позу и доплер. Статуи экспедиции слиты в тайлы.

**Облако.** ~280k лучей как у вращающегося сканера: 300 каналов по углу места (кубическое сгущение к горизонту), в канале — равный шаг по азимуту (`ringDirections`). Вершинный шейдер берёт дистанцию из куба и ставит точку в мир (`render/lidar.ts`); размер пятна растёт с дистанцией от сканера. В шейдере: фронт волны, палитра (интенсивность / высота viridis / классы), янтарная подпись неописанных видов (`uUnknown[16]`), доплер, стирание морганием, растворение и выцветание старых облаков. Дальность — на импульс (`uRange`). Живут 3 последних облака, кубические карты переиспользуются из пула и освобождаются при рестарте.

**Eye-dome lighting** (`render/composer.ts`). Точки непрозрачные, пишут цвет и `log2(1 + глубина)` в RGBA16F. Полноэкранный проход сравнивает глубину с 8 соседями: точка за краем темнеет (не ниже `edlFloor`) — появляются контуры и объём. Там же виньетка, лёгкое зерно и экспозиция (глаза закрыты — 0). Тем же проходом рисуются детальный скан и фон титула.

**Производительность.** Сцена-мишень — слитые по тайлам 40 м меши (отсечение по фрустуму), рисуется только в момент импульса (6 граней). Кадр — только точки. Рычаги: `lidar.points`, `lidar.cubeSize`, `lidar.maxScans`.

**Детальный скан** (`render/specimenView.ts`): меш образца с повышенной детализацией, 60k точек по площади поверхности, появляются по мере скана; три прохода окраски — геометрия (угол к камере), отражение 905 нм (палитра), биолюминесценция (цвет по длине волны пика).

## Аудио
- Один `AudioContext` на всю игру (`audio/engine.ts`), будится на первом клике/клавише (`installAudioUnlock`) — до запуска камеры: после `await` камеры и модели жест «протухает», и браузер держит звук выключенным (так пропадали сигналы калибровки).
- Шина: источники → компрессор → выход; посыл → свёртка с процедурной импульсной характеристикой ночного леса (~2.5 с). Шумы (белый, розовый, коричневый) — буферы, общие для всех.
- `audio/fieldSfx.ts` — синтез без ассетов, объём — `PannerNode` HRTF, слушатель = камера. Слои: лес → напряжение → сердце → игрок → силуэт → наука (GDD → Звук).
- `audio/beep.ts` — сигналы калибровки, разные по высоте (точка, моргни, закрой, открой); каждый дублируется вспышкой на экране.

## Директор
`game/director.ts` — пейсинг угрозы: напряжение 0..1 из времени, образцов, импульсов, закрытых глаз, близости; режим силуэта (`stalk` / `approach` / `retreat` / `hunt`) и желаемая дистанция. Близкий контакт — передышка. Силуэт (`game/stalker.ts`) выполняет режим с учётом того, смотрят ли на него (`field.ts → seenStalker`: закрытые глаза, конус обзора, линия видимости, взгляд).

Детерминирован от seed и потока EyeState. Поэтому его можно тестировать реплеями, и на нём строится daily seed.

Для этого симуляция идёт с фиксированным шагом (например, 60 Гц), рендер интерполирует. От частоты кадров исход не зависит.
